# RecallLoom v0.4.4

RecallLoom v0.4.4 tightens daily-log cursor recovery and public helper-output
contracts while keeping the sidecar protocol at 1.0.

## Highlights

- Daily-log cursor repair: new `repair_daily_log_cursor.py` and dispatcher
  `repair-daily-log-cursor` surfaces preview the canonical cursor and can apply
  an explicit repair to `state.json.daily_logs`.
- Empty scaffold and legacy no-log compatibility: helpers treat empty scaffold
  logs and older no-log cursors as compatible states instead of forcing manual
  state edits.
- Operator-safe repair flow: preview is read-only; apply requires
  `--apply --yes`, supports `--expected-workspace-revision`, and is blocked by
  the package support gate when mutating actions are not allowed.
- Failure UX: shared failure payloads include `single_next_command`,
  `safe_to_retry`, `side_effect`, and `trust_effect` so operators can retry or
  stop with less guesswork.
- Provenance guard: cursor repair does not create helper receipts or claim
  historical daily-log origin; helper-evidenced state is preserved only when
  bounded current evidence supports it.
- Parser consistency: archive and read surfaces use the same daily-log parsing
  expectations for scaffold, legacy no-log, and canonical entry cursor cases.

## Compatibility

- Package version: `0.4.4`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Supported languages: English and Simplified Chinese
- Existing protocol `1.0` workspaces do not need sidecar migration.

## Upgrade

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

This release was prepared with checks covering:

- daily-log cursor preview and apply behavior
- empty scaffold and legacy no-log cursor compatibility
- repair support-gate behavior for read-only preview and mutating apply
- failure payload recovery fields and retry-safety indicators
- provenance guard behavior for non-receipt-backed cursor repair
- archive and read-surface daily-log parser consistency
- package metadata, advisory, README, SKILL, and release-note version alignment

## Known Boundaries

- This release does not change the sidecar protocol.
- Cursor repair updates only `state.json.daily_logs` and provenance metadata
  needed for the repair decision; it does not rewrite daily-log files.
- Cursor repair is not a receipt-backed mutation and does not claim historical
  helper evidence.
