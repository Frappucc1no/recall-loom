# RecallLoom v0.4.2

RecallLoom v0.4.2 adds a local provenance core for controlled project-memory
writes. It keeps the sidecar protocol at 1.0 while making helper-backed writes
more traceable and clearer about what is trusted, reviewed, or blocked.

## Highlights

- Local provenance state: sidecar status now distinguishes structural validity,
  helper-evidenced state, reviewed imports, unproven sidecar state, and
  inconsistent or tampered evidence.
- Helper receipt binding: dispatcher-issued managed-file writes, daily-log
  appends, and post-append summary sync can finalize bounded local receipts.
- Stronger pre-write freshness checks: helper writes bind to expected revisions,
  current daily-log cursors, and daily-log file digests before mutating state.
- Explicit provenance validation lanes: default validation remains structural,
  while provenance checks are available through explicit validation modes.
- Non-invasive UX gates: helper readiness reports use allow, warn, ask, and
  block posture without requiring hooks, daemons, telemetry, or host plugins.
- Public package hygiene: release and package documentation keeps installable
  files, user-facing docs, runtime helpers, and advisory metadata separate from
  maintainer-only working material.

## Compatibility

- Package version: `0.4.2`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Supported languages: English and Simplified Chinese
- Existing protocol `1.0` workspaces do not need migration.

## Upgrade

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Known Boundaries

- This release does not change the sidecar protocol.
- Local helper receipts are local evidence only. They do not prove remote
  authenticity, host enforcement, or sidecar truth outside the checked project
  files.
- Archive apply and bridge apply remain outside the receipt-backed mutating
  surface until those operations gain their own receipt support.
- Host memory, wrappers, plugins, hooks, and MCP servers remain hint or
  convenience layers, not authority for local helper evidence.
