# RecallLoom v0.4.3

RecallLoom v0.4.3 is a focused recovery-input hotfix for the local provenance
line introduced in v0.4.2. It keeps the sidecar protocol at 1.0.

## Highlights

- Recovery import via stdin: `stage_recovery_proposal.py` and
  `record_recovery_review.py` can now read prepared proposal / review content
  from UTF-8 stdin.
- File-input safety preserved: `--source-file` remains deny-first and continues
  to require the existing prepared-input safety checks.
- Legacy sidecar recovery unblocked: structurally readable legacy sidecars can
  complete the reviewed-import path before their next revision-checked helper
  write.
- Provenance semantics unchanged: review import does not claim helper evidence;
  only a later receipt-finalized helper write can do that.

## Compatibility

- Package version: `0.4.3`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Supported languages: English and Simplified Chinese
- Existing protocol `1.0` workspaces do not need sidecar migration.

## Upgrade

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

This release was prepared with checks covering:

- recovery proposal / review stdin input
- source-file safety rejection for ordinary project and external files
- legacy review import followed by a receipt-finalized helper write
- existing provenance, legacy import, public surface, and non-invasive UX checks
- package metadata, advisory, README, SKILL, and release-note version consistency
- public release readiness and support-advisory parity after publication

## Known Boundaries

- This release does not change the sidecar protocol.
- `--source-file` remains intentionally restricted. Use stdin for manual
  recovery proposal / review input unless a trusted wrapper provides a prepared
  helper scratch file.
- Archive apply and bridge apply remain outside the receipt-backed mutating
  surface until those operations gain their own receipt support.
