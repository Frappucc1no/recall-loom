# RecallLoom v0.4.6.1

RecallLoom v0.4.6.1 is an emergency bugfix on the v0.4.6 line. It keeps the
sidecar protocol at `1.0` and is recommended for users on v0.4.6 or older.

## Fixes

- Upgraded workspaces with valid historical helper receipts can append again
  when the stored receipt chain uses the known v0.4.6 pre-recording provenance
  identity.
- The receipt-store validator now accepts only the current preflight identity
  and the exact known historical identity needed for finalized stored receipts.
  New receipts still use the active contract.
- `record --plan` now treats explicit no-write confirmation language such as
  "do not record this", "不用记录", and "只是确认" as no-write before layer hints
  can turn the plan into append-ready guidance.
- `record --plan` no longer exposes an executable mutating command when the
  current preflight payload says helper writes are not ready.

## Compatibility

- Package version: `0.4.6.1`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Existing protocol `1.0` workspaces do not need sidecar migration.
- The existing public `v0.4.6` tag is not moved; this release uses a new
  immutable v0.4.6-line version.

## Upgrade

Users on v0.4.6 or older should update.

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

This bugfix was prepared with private/local validation covering:

- Python compile checks for the touched runtime modules
- upgraded-workspace receipt-store summary loading with legacy receipts
- append on a private upgraded sidecar copy from legacy receipt revision to a new
  active-contract finalized receipt
- full provenance validation after the private append
- `record --plan` no-write classification for explicit confirmation language
- blocked-preflight planner behavior with no executable mutating command
- public surface hygiene excluding tests, fixtures, private validation evidence,
  release-gate artifacts, helper receipts, `.recallloom`, `.DS_Store`, and
