# RecallLoom v0.4.8.3

RecallLoom v0.4.8.3 is a Windows write-recovery hotfix for the workspace write
lock and for the failure guidance shown when a workspace becomes write-locked.

## Fixed

- On Windows, a leftover `.recallloom.write.lock` file could make every later
  write fail. The process-liveness probe used to reclaim a stale lock relied on
  `os.kill(pid, 0)`, which on Windows can terminate an unrelated live process
  or fail with an uncaught error that was reported as a damaged sidecar.
  Liveness is now probed through the Windows process API with a fail-safe
  mapping: only a confirmed non-existent pid counts as dead, and any other
  probe failure leaves the lock in place.
- POSIX lock behavior is unchanged.

## Improved

- When the rolling summary falls too far behind for post-append sync, the
  refusal now names the official recovery path (a dispatcher current-state
  write) instead of pointing back at the same rejected command.
- Blocked writes now route each failure family to its own next step:
  re-run preflight and retry for stale write context, the recovery
  proposal/review/promotion lane for integrity-review states, and
  inspect-first lock handling for lock conflicts. High-risk states never
  receive an executable write suggestion.
- Plain-text failure output from the direct helper gates now includes the
  specific reason code instead of only a generic category message.

## Safety And Compatibility

- Package version: `0.4.8.3`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Existing workspaces do not need sidecar migration or historical receipt
  rewriting.
- The post-append summary sync contract and all write gates are unchanged;
  this release changes liveness handling and failure guidance only.
- Lock files keep their existing location, format, and manual unlock flow;
  forced removal still requires an explicit flag.

## Upgrade

Upgrade is recommended for all users, and especially for Windows users and
anyone who hit a stuck or repeatedly failing write on v0.4.8.2. This patch
does not raise the minimum mutating or read-only package version.

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

Validation covered the Windows liveness matrix (dead pid, access denied, and
other probe failures), end-to-end stale-lock reclaim on the Windows branch,
POSIX behavior pinning, the unlock tool in inspect and explicit modes, the
per-family failure routing including cross-family isolation, the full
stale-summary escape path, and strict-gate states emitting no write
suggestion. Validation assets and private release evidence are not included
in the public package.
