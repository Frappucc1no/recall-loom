# RecallLoom v0.4.8.1

RecallLoom v0.4.8.1 is the recommended stable compatibility hotfix for users
who have project memory recorded with the public v0.4.6.2-v0.4.7 recording
implementation.

## Fixed

- v0.4.8 could incorrectly reject legitimate finalized receipts created by
  the v0.4.6.2-v0.4.7 recording implementation as
  `receipt_store_contract_invalid`.
- v0.4.8.1 accepts that one frozen historical provenance contract identity in
  addition to the current and already-supported legacy identities.

## Safety And Compatibility

- Unknown, inconsistent, damaged, or mismatched receipt identities remain
  rejected. This is not a general integrity bypass.
- Existing receipts are read as written; the release does not migrate,
  rewrite, delete, or recalculate historical receipt records.
- Package version: `0.4.8.1`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Existing protocol `1.0` workspaces do not need sidecar migration.
- Network access remains optional for local use and is limited to version and
  repository support information when available.

## Upgrade

Upgrading is recommended for v0.4.8 users whose workspaces contain receipts
created by v0.4.6.2 or v0.4.7. Other protocol `1.0` workspaces remain
compatible, and this patch does not raise the minimum mutating or read-only
package version.

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

Validation covered the historical receipt fixture, current and legacy accepted
identities, an internally consistent unknown-identity negative case, a full
dispatcher write after upgrade, the affected provenance subsystem, the full
project suite, and an extracted-package workflow. Validation assets and private
release evidence are not included in the public package.
