# RecallLoom v0.4.6

RecallLoom v0.4.6 is a recommended update for all users. It adds a recording
workflow fast lane for "record this progress" use cases while keeping the
sidecar protocol at 1.0.

## Highlights

- Recording plan surface: dispatcher `record --plan` classifies a recording
  intent, returns the ordered helper path, and names the current safe command
  without writing sidecar state.
- Record taxonomy: append-only, current-state, stable-context, protocol-rule,
  simple multi-layer plan, metadata refresh, amend, duplicate no-op,
  defer/no-write, ambiguous, and unsafe paths now share a single output
  contract.
- Metadata-only post-append refresh: `sync-current-state-after-append
  --reuse-current-summary` can refresh controlled summary metadata when preflight
  proves a single append delta and the caller supplies a bound
  semantic-unchanged assertion.
- Compact output: `record --plan --compact --json` keeps human topline,
  next-action, and safety receipt fields without hiding revision, freshness,
  side-effect, privacy, or receipt signals.
- Public-safe recording templates: `references/recording-workflow.md` documents
  safe input shapes, retry templates, and metadata-only assertion requirements.
- Compatibility hardening: v0.4.5 receipt store identities remain accepted for
  read/append compatibility while new receipts use the active contract.
- Quick-summary label hardening: incidental package, tool, path, and version
  tokens are less likely to be mistaken for the project label.

## Compatibility

- Package version: `0.4.6`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Supported languages: English and Simplified Chinese
- Existing protocol `1.0` workspaces do not need sidecar migration.

## Upgrade

This is a recommended stable update for users on older RecallLoom versions.
The release advisory marks older packages as `upgrade_recommended` while
keeping the hard minimum read/write versions unchanged.

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

This release was prepared with private/local validation covering:

- `record --plan` classification, ordered path, compact output, and zero
  side-effect behavior
- append-only, current-state, stable-context, protocol-rule, multi-layer,
  duplicate no-op, no-write, ambiguous, and unsafe recording cases
- metadata-only refresh success, missing assertion rejection, stale plan/input
  digest rejection, preflight digest mismatch rejection, changed body digest
  rejection, and controlled-metadata whitelist enforcement
- package support blocking for mutating refresh under `unknown_offline` and
  `readonly_only`
- receipt finalization failure, malformed receipt fail-closed behavior, and
  v0.4.5 receipt store read/append compatibility
- quick-summary label extraction hardening
- public surface hygiene excluding tests, fixtures, private validation evidence,
  release-gate artifacts, helper receipts, `.recallloom`, `.DS_Store`, and
  local-only logs

## Known Boundaries

- This release does not change the sidecar protocol.
- `record --plan` is read-only and plan-only; it does not perform bundled
  multi-layer writes.
- `record --apply` remains out of scope for this release.
- Metadata-only refresh is not a semantic summary rewrite. If the append changes
  current-state meaning, use the normal current-state update path instead.
