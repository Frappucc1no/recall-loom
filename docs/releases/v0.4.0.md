# RecallLoom v0.4.0

RecallLoom v0.4.0 makes long-running projects easier to resume across AI
sessions and tools: restore paths are shorter, current state is separated more
clearly from background material, progress logging can sync current state more
directly, and write-safety boundaries are clearer. This release remains
compatible with sidecar protocol 1.0, so existing protocol 1.0 workspaces do
not need migration.

## Highlights

- More reliable project restore: RecallLoom prioritizes current state, active
  judgments, and next steps before expanding into background material or
  history, reducing stale-context interference.
- Smoother progress capture: structured progress entries and the post-append
  current-state sync path keep "what just changed" aligned with "where to
  continue next".
- Safer long-term memory writes: revision checks, freshness checks, source-file
  boundaries, and scratch-residue handling reduce the risk of saving stale or
  unintended content into project memory.
- Clearer multi-tool collaboration boundaries: Codex, Claude Code, Gemini CLI,
  OpenCode, and other hosts may provide entrypoints or convenience commands,
  while project truth remains in workspace-local RecallLoom files.
- Clearer public entrypoints and package metadata: README, USAGE, SKILL, and
  package metadata now describe their responsibilities more consistently across
  install, restore, update, and optional native-wrapper flows.
- Stronger privacy and output hygiene: public-safe handling continues for local
  paths, token-like values, host metadata, and external-source summaries.

## Compatibility

- Package version: `0.4.0`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Supported languages: English and Simplified Chinese
- Existing protocol `1.0` workspaces do not need migration.

## Upgrade

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

This release was prepared with checks covering:

- package metadata, advisory, README, and SKILL version consistency
- contract documentation sync
- RecallLoom helper and entrypoint behavior
- public-surface privacy and hygiene
- whitespace and diff hygiene

## Known Boundaries

- RecallLoom still uses project-local files as the source of truth and does not
  require a database, background service, or RAG pipeline.
- Host memory remains hint-only; it is not the source of truth.
- Native wrappers are convenience entrypoints over the same package helpers.
- RecallLoom does not automatically edit product code; it manages
  project-continuity files unless invoked by the user workflow.
