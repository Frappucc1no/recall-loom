# RecallLoom v0.4.8

RecallLoom v0.4.8 is a recommended stable reliability and safety update. It
keeps the sidecar protocol at `1.0`, requires Python `3.10+`, and does not
require sidecar migration for existing protocol `1.0` workspaces.

## Highlights

- Sequential managed-file writes after initialization no longer become blocked
  just because one initialized file has received its first helper receipt while
  another is still on its untouched scaffold.
- Write failures now distinguish verified no-receipt outcomes that can be
  retried after fresh preflight from uncertain or inconsistent outcomes that
  still require review.
- A narrow, explicit review path is available for eligible target-only
  post-write verification failures when the sidecar state still matches the
  expected snapshot. It does not automatically approve or rewrite project
  memory.
- Status, preflight, validation, and recovery responses route to a safer single
  next step and avoid presenting a mutating retry when the evidence does not
  support one.
- Local diagnostic, read, and write actions can continue when the version
  advisory cannot be reached and no cached policy exists. Valid cached
  restrictions still apply.
- Approximate text such as `~40` or `~60s` is no longer treated as a home path,
  while real POSIX, Windows drive, and UNC paths remain protected in output.
- Legitimate project-owned symlinked scan roots no longer trigger scratch
  residue blocks. Managed-root redirection and untrusted scratch markers remain
  blocked.
- Bidirectional override controls are rejected by the existing attached-text
  safety scan.
- Initialization and later helpers now use the same `03:00` logical-workday
  boundary, including the midnight-to-rollover interval.
- Public operation guidance now matches the shipped surface: bridge and archive
  changes remain preview-only, and direct mutating helpers require fresh
  preflight context.

## Safety And Compatibility

- Unknown, inconsistent, damaged, or mismatched sidecar evidence still fails
  closed. This release does not add a general integrity bypass or automatic
  recovery center.
- Reviewed recovery is intentionally narrow, binding-based, and followed by a
  fresh validation/preflight cycle plus explicit confirmation before the first
  later write.
- Network access remains optional for normal local use. When available, the
  public advisory still communicates version recommendations and explicit
  read/write minimums.
- Package version: `0.4.8`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Existing protocol `1.0` workspaces do not need sidecar migration.

## Upgrade

Upgrading to v0.4.8 is recommended for all users. Earlier v0.4 packages remain
protocol compatible; this release does not raise the minimum mutating or
read-only package version.

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

Validation for v0.4.8 covered:

- initialization followed by sequential managed-file writes and daily-log
  appends
- retryable, review-required, and blocked failure routing, including eligible
  reviewed recovery and negative cases
- offline package-support behavior and valid cached-policy enforcement
- path privacy, approximate-text handling, symlink boundaries, bidi controls,
  and logical-workday rollover behavior
- extracted-package help, initialization, validation, status, preflight,
  recording-plan, dry-run write, and append flows
- clean installable package contents without project memory, caches, logs, or
  maintainer-only files

## Known Boundaries

- Bridge and archive changes remain preview-only in this release.
- Reviewed recovery does not prove cryptographic authorship and does not make a
  generally inconsistent or tampered sidecar writable.
- Network checks remain limited to version/support information; RecallLoom does
  not require a background service or continuous connection.
