# RecallLoom v0.4.1

RecallLoom v0.4.1 is a follow-up hardening release for the v0.4 line. It
keeps the sidecar protocol at 1.0 while tightening recovery, support-state, and
public-output boundaries.

## Highlights

- Recovery source input hardening: recovery helper inputs are checked more
  carefully before they can promote or record long-term project memory.
- Support-cache fail-closed behavior: mutating actions stay blocked when package
  support cannot be verified because the available support state is stale or
  offline.
- Public failure path redaction: user-facing failure payloads avoid exposing
  local filesystem paths when reporting blocked or invalid helper operations.
- Managed recovery directory boundary hardening: recovery-directory symlink
  handling is stricter so helper operations stay inside the intended managed
  boundary.
- README, package metadata, and advisory version alignment for the 0.4.1
  package line.

## Compatibility

- Package version: `0.4.1`
- Sidecar protocol: `1.0`
- Python: `3.10+`
- Supported languages: English and Simplified Chinese
- Existing protocol `1.0` workspaces do not need migration.

## Upgrade

Skills CLI:

```bash
npx skills update
```

Directory install:

Replace the installed `recallloom/` skill directory with this release package.

Native wrappers:

Rerun `install_native_commands.py` after updating if native commands are
installed.

## Validation Summary

This release was prepared with checks covering:

- package metadata, advisory, README, and SKILL version consistency
- contract documentation sync
- RecallLoom helper import/compile health
- public release readiness, including support-advisory parity after publication
- whitespace and diff hygiene

## Known Boundaries

- This release does not change the sidecar protocol.
- RecallLoom still uses project-local files as the source of truth and does not
  require a database, background service, or RAG pipeline.
- Host memory remains hint-only; it is not the source of truth.
- Native wrappers are convenience entrypoints over the same package helpers.
- Final publication steps such as tags, GitHub Releases, and security advisory
  updates are separate release operations.
